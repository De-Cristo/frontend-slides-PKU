The Problem: Knowledge is scattered across Confluence, TWiki, Indico, eLogs, and expert memory. Shifters face navigation barriers.
Document Fragmentation
Hardware specs, procedure runbooks, and parameters are hard to cross-reference.
Centralized Reference Goal
A structured reference and navigation layer that bridges Engineering, DAQ, and Operations.
  • Harvester CLI: Automated Confluence scraping and manual source adapters.
  • Raw Preservation: Storing scraped files in a version-controlled raw archive to guarantee provenance.
  • Wiki Compilation: LLM-based concept extraction and interlinked markdown output.
  • Quartz Static Site: Published static site running via GitLab CI Pages.
  • Local execution: Inference runs securely on CERN-approved local models (Ollama/CERN portals).
  • Component Separation: Clean separation of harvester, compiler, and published wiki.

Pillar A: Living Knowledge Base

A portably structured technical repository serving as a source-backed reference and navigation layer.

Official authority remains the original approved procedures and logs; the wiki indexes them.

Pillar B: Operation Assistant

A supervised, read-only commissioning shadow assistant running in a deterministic orchestration layer.

Acts as a diagnostic helper drafting reports for shifters; no autonomous control capabilities.

Design References (Not CERN Standards):
  • LLM Wiki: Compiling raw notes into compounding, interlinked markdown.
  • GBrain Agent Brain: Open-source agent memory layer (GitHub: garrytan/gbrain).
  • OKF Packaging: Markdown + YAML frontmatter for portability (Google Cloud Open Knowledge Format).
Source Authority Model:
  • Authoritative: Approved procedures, official Confluence/TWiki pages, runbooks.
  • Contextual: Meeting minutes, Indico slides, elog discussions.
  • Derived: Generated wiki pages, summaries, contradiction reports.
Architecture Layers
  1. Raw Source Archive: Untouched scraper provenance.
  2. Curated Wiki: Markdown drafts transitioning to expert-approved.
  3. Derived Brain/Index: SQLite FTS5 indices, vector embeddings.
Governance Rules
  • Strict Provenance: YAML must link back to scraped source URLs.
  • Review tags: Explicit display of review status.
  • Safety gate: High-risk runbooks require manual coordinator sign-off.
  • Supersessions: Old pages header-flagged as superseded.
  • Contradictions: Flagged and preserved as warnings.
Pi Code / Minimal Harness Philosophy: Bounded, predictable execution.
  • The LLM is **not** the controller; workflow, permissions, and logs are governed by a deterministic orchestration layer.
  • The LLM acts strictly as a stateless reasoning and drafting utility.
  • All tools are permissioned and restricted to read-only actions.
  • Operates exclusively in **shadow mode** with no direct write capabilities to detector control hardware.

MVP-1: Hardened Knowledge Base Schema — YAML frontmatter, strict provenance links, expert review flags, and markdown parsing.

MVP-4: Read-Only Shadow Assistant — Run deterministic harness on commissioning/log data.
MVP-5: Expert Validation Review — Audit diagnostics and alert rates against human operators.
  • CERN IT AI Activities Collaboration: Seek access to CERN-local inference model portals, hosted database indexing (e.g., PostgreSQL with pgvector), and OIDC authentication guidance.

  • Pre-Operations validation: Conduct rigorous evaluations of the shadow assistant's citation accuracy and false-alert rates prior to operational Run 4 readiness review.
